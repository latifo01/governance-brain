# Security policy

## Supported versions

Security fixes currently target the `main` branch. A published release is a
versioned snapshot; older release tags have no separate maintenance commitment
unless their release notes explicitly say otherwise.

Published versions and security-related release notes are listed in
[GitHub Releases](https://github.com/latifo01/governance-brain/releases).

## Report a vulnerability

Use GitHub's **Security → Report a vulnerability** option when it is available
for the repository. Otherwise, contact the repository owner, **@latifo01**,
through an available private contact channel listed on the
[maintainer's GitHub profile](https://github.com/latifo01). If no private channel
is available, request one without disclosing the vulnerability details.

Do not disclose an unpatched vulnerability, credentials, personal data or
confidential source content in a public issue or pull request.

A useful report contains:

- the affected release tag or commit and operating environment;
- the affected component and expected versus observed behaviour;
- minimal reproduction steps using synthetic data;
- the potential impact and any suggested remediation.

Use source identifiers, hashes and locators when provenance is relevant.
Avoid attaching source originals, ingest text, project answers or secrets.

## Handling reports

The maintainer will assess the report, request clarification when needed and
coordinate remediation and disclosure with the reporter. There is no guaranteed
response or fix deadline. Confirmed fixes and affected-version information can
be documented in GitHub Releases and, where appropriate, a security advisory.

For community-conduct concerns, see [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md).
